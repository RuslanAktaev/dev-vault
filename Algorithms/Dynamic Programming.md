# Dynamic Programming

**Определение.** Решение задачи через ответы на **перекрывающиеся подзадачи**, каждая считается один раз. Нужны два свойства:
- **Optimal substructure** — оптимум собирается из оптимумов подзадач;
- **Overlapping subproblems** — одни и те же подзадачи встречаются многократно. Без этого получается просто «разделяй и властвуй».

## Два способа
- **Top-down (мемоизация)** — рекурсия + кэш по состоянию. Проще написать, считаются только нужные состояния, но есть риск переполнить стек.
- **Bottom-up (табуляция)** — заполнить таблицу в порядке зависимостей. Нет рекурсии, легко оптимизировать память.

## Рецепт
1. **Состояние** — что однозначно описывает подзадачу: `dp[i]`, `dp[i][j]`.
2. **Переход** — как состояние выражается через меньшие.
3. **База** — тривиальные состояния.
4. **Порядок** вычисления — зависимости должны быть посчитаны раньше.
5. **Ответ** — какое состояние (или максимум по каким).

Сложность = **число состояний × стоимость перехода**.

## Классика
Фибоначчи, подъём по лестнице, 0/1-рюкзак, размен монет, LIS, LCS, edit distance, пути в сетке.

```js
// размен: минимум монет на сумму
const dp = Array(amount + 1).fill(Infinity); dp[0] = 0;
for (let s = 1; s <= amount; s++)
  for (const c of coins) if (c <= s) dp[s] = Math.min(dp[s], dp[s - c] + 1);
```

**Оптимизация памяти**: если `dp[i]` зависит только от `dp[i−1]`, хватит двух строк или одной (rolling array).

## Частые ошибки понимания
- Плохо выбранное состояние: чего-то не хватает, и переход неоднозначен. Это главная сложность DP, код вторичен.
- DP ≠ «запомнить результаты функции». Мемоизация — только техника. Суть в разбиении на подзадачи.
- В 0/1-рюкзаке с одномерным массивом идти по весу **в обратную сторону**, иначе предмет возьмётся дважды.

## Связи
- [[Greedy]] — оба опираются на optimal substructure. DP — когда жадный выбор не гарантирует оптимума.
- [[Graphs]] — DP — это кратчайший путь в DAG состояний. Bellman-Ford — DP.
- [[Hash Tables]] — мемо-кэш для top-down, когда состояния разреженные или составные.
- [[Complexity]] — мемоизация превращает экспоненту в полином.
