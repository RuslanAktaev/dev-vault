# Greedy

**Определение.** На каждом шаге делается **локально оптимальный выбор**, без возврата назад. Работает, только если локальные выборы гарантированно складываются в глобальный оптимум.

## Когда работает
Нужны два свойства:
- **Greedy-choice property** — существует оптимальное решение, которое начинается с жадного выбора.
- **Optimal substructure** — после выбора остаётся такая же задача меньшего размера.

Доказывается обычно **аргументом обмена** (exchange argument): любое оптимальное решение можно, не ухудшая, превратить в то, что начинается с жадного выбора.

## Классика
- **Interval scheduling**: максимум непересекающихся интервалов — сортировать **по концу** и брать первый подходящий.
- **Dijkstra**, **Prim**, **Kruskal** (MST).
- **Huffman** — сжатие.
- **Дробный рюкзак** — по удельной ценности.

## Контрпримеры
- Монеты `{1, 3, 4}`, сумма 6: жадно 4 + 1 + 1 = 3 монеты, оптимум 3 + 3 = 2 монеты. Для произвольных номиналов нужно DP.
- **0/1-рюкзак** — жадный выбор по удельной ценности не оптимален, решается DP.

## Частые ошибки понимания
- «Кажется, работает на примерах». Без доказательства (или контрпримера) жадность — гипотеза.
- Сортировать по неправильному ключу: интервалы по началу или длине вместо конца.
- Жадность — эвристика для NP-трудных задач (set cover). Там она даёт приближение, а не оптимум.

## Связи
- [[Dynamic Programming]] — у обоих optimal substructure. Жадность выбирает один вариант, DP перебирает все подзадачи. Когда жадность ломается, помогает DP.
- [[Graphs]] — Dijkstra и MST — жадные алгоритмы.
- [[Sorting]] — жадный алгоритм обычно начинается с сортировки по правильному ключу.
