# Hash Tables

**Определение.** Структура «ключ → значение». Хеш-функция превращает ключ в индекс бакета. Вставка, поиск и удаление — **O(1) в среднем**.

## Как устроено
- **Коллизии** — разные ключи попадают в один бакет:
  - **chaining** — в бакете список (или дерево);
  - **open addressing** — поиск следующей свободной ячейки (linear / quadratic probing, double hashing).
- **Load factor** = элементы / бакеты. При превышении порога таблица увеличивается и всё **перехешируется**. Отдельная вставка — O(n), амортизированно — O(1).
- Худший случай O(n): плохая хеш-функция или атака коллизиями.
- Порядка нет, запросов по диапазону тоже. Для них нужно дерево.

## В JavaScript
- **`Map`** — ключи любого типа, порядок вставки, `size`, быстрые частые вставки и удаления.
- **`Object`** — ключи приводятся к строкам (или Symbol), есть прототипные ключи. Удобен для статических записей и JSON.
- **`Set`** — множество: дедупликация, быстрый `has`.
- `WeakMap` / `WeakSet` — ключи-объекты, не мешают сборке мусора (кэши метаданных).
- Объекты как ключи `Map` сравниваются **по ссылке**: `map.get({ id: 1 })` не найдёт ранее положенный `{ id: 1 }`.

## Типовые приёмы
Подсчёт частот, дедупликация, two-sum (ищем `target − x` за O(1)), группировка, индекс по id, мемоизация.

## Частые ошибки понимания
- O(1) — гарантия. Это средний случай.
- Использовать `Object` как словарь с пользовательскими ключами (`__proto__`, `constructor`). Лучше `Map` или `Object.create(null)`.
- Ожидать, что `obj[1]` и `obj['1']` — разные ключи.
