# Sorting

## Основные алгоритмы
| Алгоритм | Среднее | Худшее | Память | Стабильный |
|---|---|---|---|---|
| Insertion | n² | n² | 1 | да |
| Merge | n log n | n log n | n | да |
| Quick | n log n | n² | log n | нет |
| Heap | n log n | n log n | 1 | нет |
| Counting / Radix | n + k | n + k | n + k | да |

- **Нижняя граница для сортировки сравнениями — Ω(n log n).** Быстрее работают только сортировки без сравнений (counting, radix): они используют структуру ключей.
- **Insertion sort** хорош на маленьких и почти отсортированных массивах, поэтому его используют гибридные алгоритмы.
- **Quick sort** — худший случай n² на неудачном опорном элементе (pivot). Случайный pivot и median-of-three помогают.
- **Стабильность** — равные элементы сохраняют исходный порядок. Важно при сортировке по нескольким ключам по очереди.

## В JavaScript
- `Array.prototype.sort` **стабилен** (с ES2019), в V8 это TimSort (merge + insertion).
- **По умолчанию сравнивает как строки**: `[10, 9, 1].sort()` → `[1, 10, 9]`. Для чисел: `sort((a, b) => a - b)`.
- `sort` мутирует массив. `toSorted()` (ES2023) возвращает новый.
- Компаратор должен быть консистентным: возвращать число, а не boolean.

## Частые ошибки понимания
- Сортировать там, где хватит одного прохода (min/max, top-k через кучу за O(n log k)).
- Считать, что quicksort всегда быстрее merge sort.
