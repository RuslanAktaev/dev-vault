# Search

## Линейный поиск
O(n). Работает на любых данных, другого варианта для неупорядоченного массива нет.

## Бинарный поиск
O(log n). Требует **отсортированных** данных (или, шире, монотонного предиката).

```js
function lowerBound(a, x) {      // первый индекс, где a[i] >= x
  let lo = 0, hi = a.length;     // полуинтервал [lo, hi)
  while (lo < hi) {
    const mid = (lo + hi) >> 1;
    if (a[mid] < x) lo = mid + 1; else hi = mid;
  }
  return lo;
}
```
- **Поиск по ответу**: если «подходит ли значение k?» монотонно (false…false true…true), бинарным поиском ищется граница. Примеры: минимальная скорость, максимальная вместимость.
- Держи **один инвариант** на границах (`[lo, hi)` или `[lo, hi]`) и не смешивай.

## Другие виды поиска
- **Хеш-таблица** — O(1) в среднем по ключу, но без порядка и диапазонов.
- **BFS / DFS** — поиск в графах и деревьях (см. Graphs).

## Частые ошибки понимания
- Бесконечный цикл при `lo = mid` без `+1` и округлении вниз.
- Off-by-one: возвращать `lo` или `lo − 1`, `<` или `<=`. Решается формулировкой «первый элемент, где предикат true».
- Бинарный поиск на неотсортированных данных или сортировка ради одного поиска: O(n log n) хуже линейного O(n).
