# ETag

**Определение.** ETag — отпечаток версии ответа. Сервер считает его от содержимого и отдаёт в заголовке `ETag`. С ним кеш может спросить сервер «изменилось ли что-то» и, если нет, не качать тело заново. Эту сверку перед каждым использованием копии и требует `no-cache`.

## Сверка по шагам
1. Первый запрос: сервер отвечает `200 OK` с `ETag: "v7"` и телом. Браузер сохраняет копию вместе с отпечатком.
2. Срок свежести вышел (или стоит `no-cache`), и браузер спрашивает с заголовком `If-None-Match: "v7"`, то есть «пришли файл, только если у тебя сейчас не `v7`».
3. Сервер сверяет. Совпало — `304 Not Modified` без тела, браузер берёт копию из кеша. Не совпало — `200 OK` с новым телом и новым `ETag`.

Копия всегда свежая (её сверили с сервером), а тело пересылается только при изменении. Аналог по времени: `Last-Modified` + `If-Modified-Since`.

На клиенте делать ничего не нужно. Если у браузера есть копия с ETag и её нужно сверить (`no-cache` или истёк `max-age`), он сам пришлёт `If-None-Match`. Сверку ломают `fetch(..., { cache: 'no-store' })` и галка «Disable cache» в DevTools.

## Откуда берётся и что экономит
ETag формирует только сервер. Браузер хранит значение вместе с копией и возвращает его в `If-None-Match`.

| Способ | Что сравнивается | Считается на каждом запросе? |
|---|---|---|
| Хеш тела ответа (по умолчанию в Express) | Хеш собранного ответа | Да, даже если в итоге ответ `304` |
| Версия записи (`version`, `updated_at`) | Поле из БД | Нет. Сравнить можно до сборки ответа |
| Метаданные файла (nginx, статика) | Размер и время изменения | Нет |
| Хеш в имени файла | Хеш, посчитанный при сборке | Нет |

**Хеш тела экономит только трафик.** На каждый запрос всё равно выполняется всё: запрос к БД, сборка ответа, хеш, сверка. При `304` не передаётся только тело. Чтобы экономить и работу бэкенда, сверяют дешёвый признак (версию записи) **до** сборки ответа.

**Главное требование:** ETag обязан меняться при любом изменении содержимого. Иначе сервер будет и дальше отвечать `304` на устаревшие данные.

## Код
**Express**, ETag по версии записи:

```js
app.get('/api/orders/:id', async (req, res) => {
  const order = await db.orders.find(req.params.id);
  res.set('ETag', `"${order.version}"`);
  res.set('Cache-Control', 'private, no-cache');
  if (req.fresh) return res.status(304).end();   // If-None-Match совпал
  res.json(order);
});
```

Для `res.send` и `res.json` Express сам делает слабый ETag (настраивается через `app.set('etag', ...)`).

**Next.js.** Для страниц и API Routes в Pages Router ETag и `304` обрабатывает сам сервер Next. Route Handler в App Router возвращает твой `Response` как есть. Там `If-None-Match` сравнивают вручную и отвечают `new Response(null, { status: 304 })`.

## Частые ошибки понимания
- **«ETag разгружает бэкенд».** С хешем тела — нет, экономится только трафик. Работу экономит сверка по версии записи до сборки ответа.
- **ETag, который не меняется при изменении данных.** Пользователь навсегда застрянет на старой копии.
- **«ETag генерирует браузер».** Нет, только сервер. Браузер его хранит и возвращает.
- **Ждать `If-None-Match` при включённом «Disable cache».** Браузер его не пришлёт.
