# Web MOC

Сервер ничего не помнит и никому не доверяет. Браузер автоматически делает то, о чём его не просили, и сам решает, что показать странице. Почти все темы ниже отвечают на вопрос, как с этим жить.

Порядок чтения: заголовки → куки → сессии → CORS → OAuth → PKCE → OIDC. Кеширование: HTTP-кеш → ETag → CDN → подписанные ссылки → Redis. Безопасность: HTTPS и TLS → HSTS → CSRF → XSS и CSP.

- [[HTTP-заголовки]] — имя, значение, директива. Заголовки, которые встречаются постоянно.
- [[Идемпотентность и чистые функции]] — детерминированность, чистота, два смысла идемпотентности, safe/cacheable HTTP-методы, Idempotency-Key.
- [[Cookies]] — атрибуты, SameSite и что пропускает Lax, Domain/Path, префиксы, формат `Set-Cookie`, origin против site.
- [[Сессии и JWT]] — серверная сессия по шагам, устройство и проверка JWT, где хранить токены.
- [[CORS]] — SOP, preflight, заголовки ответа, настройка в Express/Next.js/Laravel, что ломается.
- [[OAuth 2.0]] — роли, регистрация клиента и секреты, Authorization Code + PKCE, flows, OAuth 2.1.
- [[PKCE]] — `code_verifier` и `code_challenge`, два канала, что PKCE даёт и чего не даёт.
- [[OIDC]] — `id_token`, `nonce`, discovery и JWKS, связывание пользователя по (`iss`, `sub`).
- [[HTTP-кеширование]] — директивы `Cache-Control`, личный и общий кеш, `public`/`private`, хеш в имени файла, `Vary`, как проверить.
- [[ETag]] — сверка и `304`, откуда берётся ETag и что он реально экономит.
- [[CDN]] — что делает кроме кеша, ключ копии, какие запросы через него идут, заголовки по типам ответов, Next.js, purge.
- [[Подписанные ссылки]] — личные медиа через общий кеш: три схемы, signed URL по шагам.
- [[Redis-кеш]] — cache-aside, ключи, инвалидация и гонка при обновлении, stampede, два слоя кеша.
- [[HTTPS и TLS]] — целостность против аутентификации, сертификат и SAN, центры сертификации, корневые хранилища, цепочка.
- [[HSTS]] — SSL stripping, `max-age`, preload, почему нужны и `Secure`, и HSTS.
- [[CSRF]] — атака по шагам, `Domain` против `SameSite`, дыра в `Lax`, CSRF-токен, защита слоями.
- [[XSS и CSP]] — директивы CSP, nonce, Report-Only, security-заголовки, что от чего защищает.
- [[Отладка веб-запросов]] — чеклист «симптом → куда смотреть».

## Что от чего защищает

| Механизм | Защищает от | Не защищает от |
|---|---|---|
| TLS | Чтения и подмены трафика, подмены сервера | Неизвестного клиента (нужен логин или mTLS) |
| HSTS | SSL stripping на `http://` | Первого визита без preload |
| CORS | Чтения ответа чужим сайтом | CSRF: запрос уходит, эффект происходит |
| `SameSite` | CSRF через куки | XSS, GET-действий при `Lax` |
| `HttpOnly` | Кражи куки через XSS | Использования сессии скриптом |
| CSP | XSS | Логических ошибок авторизации |

## Как всё соединяется: логин
1. Пользователь отправляет форму: `POST /login` по HTTPS.
2. Сервер проверяет пароль, создаёт сессию и отвечает `Set-Cookie: sid=...; HttpOnly; Secure; SameSite=Lax` → [[Сессии и JWT]], [[Cookies]].
3. Браузер сам прикладывает куку к следующим запросам. По `sid` сервер каждый раз заново восстанавливает, кто это: HTTP stateless, а состояние лежит в Redis.
4. Если фронт на другом origin, нужны CORS с credentials и `credentials: 'include'` → [[CORS]].
5. Изменяющие запросы защищены `SameSite` и при необходимости CSRF-токеном → [[CSRF]].
6. Для живых данных открывается WebSocket с проверкой Origin и тикетом.
7. При входе через Google шаги 1–2 заменяет OAuth/OIDC, а в конце всё равно создаётся своя обычная сессия → [[OAuth 2.0]], [[OIDC]].

## Ещё не разобрано

| Тема | Что нужно знать |
|---|---|
| DNS | A/AAAA (адрес), CNAME (алиас), TXT (верификации), TTL (кеш записей). Смена записи доходит не мгновенно |
| TCP и UDP/QUIC | TCP: надёжный упорядоченный поток, handshake, медленный старт. QUIC — транспорт HTTP/3 поверх UDP |
| Reverse proxy | TLS termination, `X-Forwarded-*`, кеш прокси (`proxy_cache`). CDN разобран в [[CDN]] |
| Content negotiation и сжатие | `Accept` / `Accept-Encoding`, gzip и br, `Content-Encoding` |
| Chunked transfer, Range | Потоковые ответы без `Content-Length`. Докачка и перемотка видео |
| Rate limiting | Ответ 429 с `Retry-After`. Лимиты по IP, ключу, пользователю |
| REST, GraphQL, gRPC | REST: ресурсы и HTTP-методы. GraphQL: один endpoint и запросы с выбором полей. gRPC: бинарный RPC поверх HTTP/2 |
| SSRF | Сервер по URL от пользователя ходит во внутреннюю сеть. Нужна проверка целевых адресов |
| Open redirect | Редирект на непроверенный URL из параметра. Используется в фишинге и атаках на OAuth |
| Clickjacking | Твою страницу встраивают в чужой iframe. Закрывается `frame-ancestors` (см. [[XSS и CSP]]) |
| Request smuggling, cache poisoning | Рассинхрон между прокси и сервером. Отравление кеша из-за забытого `Vary` |
| SRI, Trusted Types | Хеши внешних скриптов. Защита от DOM-XSS |
