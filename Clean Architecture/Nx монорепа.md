# Nx монорепа

Практическое применение принципов Clean Architecture к фронтенд-монорепе на Nx.

## Типы библиотек
- **feature** — умные компоненты и экраны под конкретный сценарий. Могут зависеть от всего ниже.
- **ui** — презентационные компоненты. Без знания о данных и сторе. Зависят только от `ui` и `util`.
- **data-access** — работа с данными: API-клиенты, RTK Query API, стор. Не знает о UI.
- **util** — чистые функции и типы. Зависит только от `util`. Самый стабильный слой.

## Правила границ
- Теги `type:*` и `scope:*` на проектах + lint-правило `@nx/enforce-module-boundaries`. Нарушение зависимости — ошибка линта, а не вопрос код-ревью.
- Публичный API библиотеки — только через `index.ts`. Импорты вглубь запрещены.
- Циклы запрещены. `nx graph` визуализирует граф проектов.

## Как это ложится на принципы
- **SRP/CCP** — `feature` на сценарий: изменение фичи локально.
- **ISP/CRP** — мелкие библиотеки: фича не тянет лишнего.
- **DIP/SDP** — зависимости идут к стабильному: `feature → data-access → util`. Высокоуровневое не зависит от конкретного UI.
- **ADP** — граф проектов без циклов, `nx affected` пересобирает и тестирует только затронутое.
- **Packaging** — это package by component с инкапсуляцией, которую обеспечивает инструмент.

## Частые ошибки
- Одна огромная `shared`-библиотека: нарушает CRP, каждое изменение задевает всех.
- Держать бизнес-логику в `ui`-компонентах: слой деградирует до «всё знает обо всём».
