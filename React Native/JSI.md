# JSI

**Определение.** JSI (JavaScript Interface) — C++ API, через который C++-код React Native встраивает JS-движок: регистрирует в нём свои функции и объекты, работает с JS-значениями и вызывает JS из C++. Лежит в ядре RN в готовом виде, Codegen его не генерирует. Для JS результат простой: появляются глобальные функции и объекты, за которыми стоит C++.

[[Hermes]] исполняет JS, а JSI — дверь, через которую приложение попадает в движок.

## API
- `jsi::Runtime` — движок. `HermesRuntime` — одна из реализаций.
- `jsi::Value`, `jsi::Object`, `jsi::Function` — JS-значения на стороне C++.
- `jsi::HostObject` — C++-объект, который виден в JS как обычный объект.
- `HostFunction` — C++-функция, которую можно вызвать из JS.

JSI не привязан к движку: Hermes, JSC и V8 реализуют один и тот же интерфейс.

## Что даёт по сравнению с bridge
- Нет сериализации в JSON: значения передаются напрямую.
- Вызовы прямые, возможны **синхронные**.
- JS может держать ссылку на нативный объект, а не копию данных.
- Асинхронные вызовы никуда не делись.

**Синхронный вызов блокирует JS-поток**, поэтому использовать его точечно: быстрые операции, а не тяжёлая работа.

## Что RN регистрирует при старте
Сам движок приходит без этого, всё добавляет RN через JSI (имена зависят от версии):
- прокси TurboModules — `__turboModuleProxy` / `nativeModuleProxy`;
- UIManager Fabric — `nativeFabricUIManager`;
- вспомогательные функции: нативное логирование, `performance.now`.

**Порядок старта:**
1. Создаётся Hermes.
2. RN через JSI регистрирует глобалы.
3. Hermes загружает бандл.
4. Бандл исполняется.

## Цепочка вызова
```
JS (Hermes) ⇄ JSI ⇄ C++ ⇄ Obj-C++ (iOS) / JNI (Android) ⇄ Swift / Kotlin ⇄ платформенный SDK
```
- C++, Swift и Kotlin остаются отдельными языками и вызывают друг друга через интероп, а не превращаются друг в друга.
- C++ в рантайме — обычный скомпилированный машинный код внутри приложения (`.so` на Android, бинарник на iOS), в том же процессе, что и Hermes.
- В готовом приложении исходников C++ нет, только скомпилированный код: Hermes, JSI, Fabric, Yoga, инфраструктура TurboModule, сгенерированный клей, модули.

## Частые ошибки понимания
- **«JSI делает всё синхронным».** Синхронность — возможность, а не режим. Синхронный вызов блокирует JS-поток.
- **«JSI — часть Hermes».** Это интерфейс в ядре RN, Hermes лишь одна из его реализаций.
- **«JSI генерирует Codegen».** JSI готовый, Codegen генерирует обвязку модулей поверх него.
- **«`fetch`, таймеры, `console` есть в движке».** Их собирает RN из полифилов и нативных модулей. DOM и `window` нет.

- [[New Architecture]] — JSI — фундамент, на котором стоят TurboModules и Fabric.
- [[Hermes]] — `HermesRuntime` реализует `jsi::Runtime`.
