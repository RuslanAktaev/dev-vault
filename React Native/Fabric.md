# Fabric

**Определение.** Fabric — рендерер новой архитектуры React Native с ядром на C++, общим для iOS и Android. Реконсилер и Fiber те же, что в вебе: Fiber решает, что изменилось, а Fabric доставляет это в нативный UI. Вместо `react-dom` в RN раньше был рендерер **Paper** (через bridge), теперь Fabric.

## Устройство
Рендерер из двух частей, связанных через JSI:
- **JS-сторона** — хост-конфиг для реконсилера (`nativeFabricUIManager`);
- **C++-ядро** — Shadow Tree, layout, commit, diff, mount.

## Что делает, по шагам
1. Принимает от реконсилера **хост-операции** через JSI: создать узел, клонировать, добавить ребёнка, завершить корень. Дерево файберов Fabric **не видит**, оно целиком в JS.
2. Строит иммутабельное **Shadow Tree** клонированием.
3. **Yoga** считает layout.
4. **Commit**: новое дерево становится актуальным.
5. **Diff** с тем, что сейчас смонтировано → список мутаций.
6. **Mount**: UI-поток применяет мутации к нативным view. Это единственная платформо-специфичная часть: Obj-C/Swift и Java/Kotlin.
7. События (касания, layout-колбэки) идут обратно в JS.

Сравнений два: в JS (реконсиляция по Fiber) и в C++ (diff Shadow Tree).

## Shadow Tree
- **Не новое понятие.** В старой архитектуре тоже было (`RCTShadowView`, `ReactShadowNode`), но жило только на нативной стороне: мутабельное, своё для каждой платформы, за bridge.
- В Fabric — на C++, общее для платформ, **иммутабельное**, доступно из JS через JSI.
- Содержит **только хост-узлы** (`View`, `Text`, `Image`). У функциональных компонентов своего узла нет.
- Не мутируется и не перестраивается целиком. При изменении **клонируется путь от изменённого узла до корня**, остальное переиспользуется (structural sharing). Старая версия остаётся нетронутой, поэтому другие потоки читают её безопасно. Идея та же, что у `alternate` в Fiber.
- **View flattening**: узлы, нужные только для layout (например, `View` без фона, границ и обработчиков), могут не становиться нативными view.

## Зачем diff, если Fabric и так знает об изменениях
Клонирование значит «возможно, изменилось», diff — «точно отличается от того, что на экране». Разница появляется, потому что:
- React мог клонировать узел с теми же значениями props;
- изменение могло затронуть только узлы, у которых из-за flattening нет нативных view;
- между двумя mount могло пройти несколько commit, а нужна только итоговая разница;
- layout мог дать те же размеры.

Получается два фильтра: Fiber решает, какие хост-узлы обновить, а Fabric отдаёт нативной стороне только реальную разницу.

## Yoga и layout
- Yoga — flexbox-движок на C++. Считает layout в **commit над клонированным Shadow Tree, до mount**, вне UI-потока. При обычном обновлении от React это происходит на JS-потоке, но это C++-код, а не твой JS. Пересчитываются только dirty-узлы.
- К mount у каждого узла уже есть фрейм. UI-поток применяет готовые числа (x, y, w, h) и ничего не считает.
- Поэтому layout можно прочитать из JS синхронно: `measure`, `useLayoutEffect`.
- **Алгоритм платформо-независимый, входные данные платформо-зависимые**: размер области, масштаб экрана, множитель шрифта, RTL, safe area, клавиатура, поворот приходят от хоста. Для `Text` и `TextInput` Yoga вызывает measure-функцию через платформенный слой (CoreText на iOS, свой текстовый движок на Android). Это точка, где C++ обращается к нативному коду ещё до mount.

## От `setState` до экрана
1. `setState` кладёт обновление в очередь хука, ставит lane и `childLanes`, планирует render.
2. **Render (JS)**: вызываются компоненты, элементы сверяются с файберами по `type`/`key`, строится work-in-progress, расставляются `flags`, для хост-узлов вызываются хост-операции рендерера.
3. Через JSI в C++ создаются или клонируются ShadowNode (клонируется путь до корня).
4. **Commit**: Yoga считает layout, новое Shadow Tree становится актуальным.
5. **Mount**: diff со смонтированным деревом → мутации → UI-поток применяет их к нативным view. Платформа рисует кадр.

В вебе шаги 1–2 те же, а вместо 3–5 `react-dom` в commit-фазе меняет DOM, и перерисовывает браузер.

## Где живут состояние и логика
- На JS-потоке остаются описание UI, состояние и логика: `useState`, Zustand, TanStack Query, обработчики. Fabric получает только хост-операции.
- Вне основного JS-потока: Reanimated и Gesture Handler (worklets на UI-потоке, не зависят от занятости JS), логика нативных модулей, внутреннее состояние кастомных нативных вьюх.

## Кастомная нативная вьюха
- Обычный компонент из `View` и `Text` остаётся JS-кодом, Codegen его не трогает: нативными становятся только примитивы, через общий конвейер Fabric.
- Codegen нужен для **своей нативной вьюхи** (карта, плеер, WebView). Спек описывает пропсы, события и команды, Codegen генерирует C++ для Fabric (Props, ComponentDescriptor, ShadowNode, EventEmitter) и нативные интерфейсы. Саму вьюху на Swift/Kotlin пишет разработчик.
- C++-слой нужен, потому что Shadow Tree живёт в C++, и Fabric должен знать пропсы, события, команды и как создавать ShadowNode.
- Раньше был `ViewManager` с макросами (`RCT_EXPORT_VIEW_PROPERTY`) и сопоставлением пропсов по строкам в рантайме.

```ts
// MyMapNativeComponent.ts — суффикс NativeComponent обязателен
import type { ViewProps } from 'react-native';
import codegenNativeComponent from 'react-native/Libraries/Utilities/codegenNativeComponent';

interface NativeProps extends ViewProps {
  zoom?: number;
}

export default codegenNativeComponent<NativeProps>('MyMap');
```

## Коротко для собеседования
Рендерер новой архитектуры RN. Иммутабельный Shadow Tree на C++, JSI вместо асинхронного JSON-bridge, Yoga считает layout до mount, UI-поток применяет diff. Это даёт синхронный layout и concurrent-режим React.

## Частые ошибки понимания
- **«Fabric — новый реконсилер».** Реконсилер тот же, Fabric — рендерер.
- **«Fabric видит дерево компонентов».** Только хост-узлы, полученные через хост-операции.
- **«Shadow Tree появился в Fabric».** Был и раньше, но мутабельный, нативный и за bridge.
- **«UI-поток считает layout».** Layout готов к mount, UI-поток только применяет фреймы.
- **«Для любого компонента нужен Codegen».** Только для кастомной нативной вьюхи. Компоненты из `View` и `Text` — обычный JS.
- **«Diff лишний, раз есть клонирование».** Клон — кандидат на изменение, diff отсекает то, что на экране не поменялось.
