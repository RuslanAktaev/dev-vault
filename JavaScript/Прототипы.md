# Прототипы

**Определение.** У каждого объекта есть скрытая ссылка `[[Prototype]]` на другой объект или `null`. Если свойства нет в самом объекте, движок ищет его по этой ссылке, затем по ссылке прототипа и так до `null`. На этом механизме построены `class`, `extends`, `instanceof` и все встроенные методы.

## Три разные вещи

| Что | Где есть | Что это |
|---|---|---|
| `[[Prototype]]` | У **любого** объекта, включая функции, массивы, классы, `Date`, `Map` | Скрытый слот со ссылкой на прототип. По нему идёт поиск свойств |
| `__proto__` | Геттер/сеттер на `Object.prototype` | Окошко из кода к `[[Prototype]]`. Сам ничего не хранит. Историческое имя, оставлено ради совместимости |
| `prototype` | Обычное свойство **только у функций и классов** | Объект, который `new` поставит в `[[Prototype]]` экземпляров |

- Современные аналоги `__proto__`: `Object.getPrototypeOf(obj)`, `Object.setPrototypeOf(obj, proto)`, `Object.create(proto)`.
- `Some.prototype` — не прототип самой функции `Some`. `[[Prototype]]` функции указывает на `Function.prototype`.
- Поля `__prototype__` не существует.

Ключевое равенство: `Some.prototype === Object.getPrototypeOf(a) === a.__proto__`, где `a = new Some()`.

## Поиск и запись
- **Чтение** `obj.x`: сам объект → его `[[Prototype]]` → прототип прототипа → … → `null`. Не нашли — `undefined`, не ошибка. `TypeError` бывает только при чтении свойства у `null` или `undefined`.
- **Запись** `obj.x = 1` обычно создаёт свойство в самом `obj` и прототип не трогает. Свойство прототипа с тем же именем просто перекрывается.
- `a.prototype` у экземпляра — `undefined`. `prototype` читают у функции (`Some.prototype`), а прототип экземпляра — через `Object.getPrototypeOf(a)`.

## Что делает `new F(...)`
1. Создаёт пустой объект.
2. Ставит его `[[Prototype]]` в `F.prototype`.
3. Вызывает `F` с `this` = этот объект.
4. Возвращает его, если конструктор не вернул другой **объект**. Возвращённый примитив игнорируется.

```js
function Person(name) { this.name = name; }
Person.prototype.hi = function () { return this.name; };

const p = new Person('Ann');
p.hi(); // в p нет hi → нашли в Person.prototype → вызов через точку, this = p
```

## Две цепочки
```
p      → Person.prototype   → Object.prototype → null
Person → Function.prototype → Object.prototype → null
```
- Из `Object.prototype` приходят `toString`, `hasOwnProperty`.
- Из `Function.prototype` — `call`, `apply`, `bind`.

## Направление ссылок
- **Экземпляр ссылается на прототип, а не наоборот.** Прототип о своих экземплярах не знает.
- Обратная ссылка есть только на функцию: `Some.prototype.constructor === Some`. Она создаётся автоматически, а `a.constructor` находится по цепочке.
- Это обычные ссылки на объекты: присваивание копирует ссылку, а не объект.

```
a ──[[Prototype]]──► Some.prototype ──► Object.prototype ──► null
                         └─ constructor ──► Some
Some ──.prototype──► Some.prototype
```

## Мутация против переприсваивания
- **Мутация** `Some.prototype.hi = ...` видна **всем** экземплярам, старым и новым: объект один, и каждый экземпляр идёт к нему по своей ссылке.
- **Переприсваивание** `Some.prototype = {...}` меняет только поле `prototype` у `Some`. Уже созданные экземпляры остаются на старом объекте, потому что `[[Prototype]]` фиксируется в момент `new`. Новые получат новый объект. У нового объекта нет `constructor`, пока не добавишь вручную (`Child.prototype.constructor = Child` в старом коде).
- У `class` свойство `prototype` только для чтения: переприсвоить нельзя, только мутировать.
- Старый прототип живёт, пока на него ссылается хотя бы один экземпляр.

```js
function Some() {}
const old = new Some();
Some.prototype.hi = () => 'hi';   // мутация
Some.prototype = { bye: () => 'bye' }; // переприсваивание
const fresh = new Some();

old.hi();    // 'hi'  — старый объект-прототип
old.bye;     // undefined
fresh.bye(); // 'bye'
fresh.hi;    // undefined
```

## Примитивы и `Object.create(null)`
- У примитивов своего `[[Prototype]]` нет. Но `'abc'.__proto__ === String.prototype` работает: при обращении к свойству движок временно оборачивает примитив в объект-обёртку. Так же работает `'abc'.toUpperCase()`.
- У `null` и `undefined` обёрток нет: `null.__proto__` бросает `TypeError`.
- `Object.create(null)` даёт объект без `Object.prototype` в цепочке — чистый словарь. `toString` и `hasOwnProperty` у него нет, геттер `__proto__` тоже: запись `obj.__proto__ = x` создаст обычное свойство.

## Связь с `class`
- `class` — синтаксис поверх того же механизма.
- **Методы** из тела класса (`check() {}`) лежат на `Class.prototype`: один на все экземпляры. При передаче как колбэка они теряют `this`.
- **Поля** (`x = 1`, поле-стрелка `check = () => {}`) создаются в **каждом экземпляре отдельно**: памяти больше, зато `this` у стрелки зафиксирован.
- `extends` связывает `Child.prototype` с `Parent.prototype`, а сам `Child` — с `Parent` (статические методы наследуются).
- Класс без `new` бросает `TypeError`, тело класса всегда в strict mode. Функция-конструктор без `new` в strict mode упадёт на `this.name = ...` (`this` = `undefined`), а без strict молча запишет свойства в `globalThis`.
- Стрелка, созданная в конструкторе или как поле, захватывает `this` экземпляра. Стрелка в объектном литерале берёт `this` снаружи, поэтому методы объекта пишут как `check() {}`.

```js
class Counter {
  n = 0;                      // поле: в каждом экземпляре
  inc = () => ++this.n;       // поле-стрелка: в каждом экземпляре, this зафиксирован
  get() { return this.n; }    // метод: один на Counter.prototype
}
const c = new Counter();
Object.hasOwn(c, 'inc'); // true
Object.hasOwn(c, 'get'); // false — лежит на прототипе
```

## Где используется
- **Под капотом:** `class` и `extends`; все встроенные методы (`[].map` лежит в `Array.prototype`, `toUpperCase` — в `String.prototype`); `instanceof` проверяет, есть ли `Some.prototype` в цепочке объекта; экономия памяти — один метод на все экземпляры.
- **Явно:** `Object.create(proto)`, полифиллы, миксины, наследование до `class` (`Child.prototype = Object.create(Parent.prototype)`).
- **Не стоит:** менять встроенные прототипы в прикладном коде (глобальный эффект, конфликты с будущим стандартом) и менять `[[Prototype]]` готового объекта через `setPrototypeOf` — движки теряют оптимизации.

## Коротко для собеседования
`[[Prototype]]` — скрытая ссылка любого объекта на прототип, по ней идёт поиск свойств. `__proto__` — геттер/сеттер к ней. `prototype` — свойство функции или класса: объект, который `new` ставит в `[[Prototype]]` экземпляров. Мутация прототипа видна всем экземплярам, переприсваивание — только новым.

## Частые ошибки понимания
- **«`prototype` есть у каждого объекта».** Только у функций и классов. У каждого объекта есть `[[Prototype]]`.
- **«`Some.prototype` — прототип функции `Some`».** Это прототип её будущих экземпляров. Прототип самой функции — `Function.prototype`.
- **«Прототип знает свои экземпляры».** Ссылка идёт только от экземпляра к прототипу.
- **«Переприсвоил `prototype` — обновились все экземпляры».** Только новые. Старые держат старый объект.
- **«Запись `obj.x` меняет прототип».** Создаётся собственное свойство объекта.
- **«Нет свойства — ошибка».** Будет `undefined`, ошибка только у `null`/`undefined`.
- **«Метод класса копируется в каждый экземпляр».** Методы — на прототипе, в экземпляре только поля.

## Связи
- [[This binding]] — `new` ставит `[[Prototype]]` и `this`. Метод с прототипа, найденный по цепочке, получает `this` того объекта, у которого его вызвали.
- [[Типы]] — у примитивов нет прототипа, свойства работают через временные объекты-обёртки.
- [[Функции и execution context]] — функции — объекты: у них есть и `[[Prototype]]` (`Function.prototype`), и свойство `prototype`.
