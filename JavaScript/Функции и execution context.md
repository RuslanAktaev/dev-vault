# Функции и execution context

## Execution context
**Execution context** — служебная запись движка о том, что выполняется сейчас: какие имена видны, где искать остальные и чему равен `this`. Создаётся для глобального кода, для каждого **вызова** функции, для ES-модуля и для `eval`.

Состав контекста:
- **Lexical Environment** — environment record (свои `let`, `const`, функции, параметры) + ссылка на **внешнее** окружение (outer). Если имени нет в своём record, поиск идёт по outer выше, вплоть до глобального. Цепочка outer-ссылок — это scope chain.
- **Variable Environment** — для `var`: она видна во всей функции, а не в блоке.
- **This binding** — значение `this`.

| Часть | Что хранит | От чего зависит |
|---|---|---|
| Lexical Environment | `let`, `const`, функции, параметры, outer | от места, где функция написана |
| Variable Environment | `var` | от места, где функция написана |
| This binding | `this` | от способа вызова |

```js
const a = 1;
function outer() {
  const b = 2;
  function inner() {
    const c = 3;
    console.log(a, b, c); // c — свой record, b — outer, a — outer от outer
  }
  inner();
}
```

## Когда создаётся контекст
- **Глобальный** — один раз, при запуске скрипта, до первой строки.
- **Функции** — в момент **вызова**, а не заранее, и **заново на каждый вызов**: три вызова `f()` — три контекста со своими локальными переменными. При рекурсии на стеке одновременно лежат несколько контекстов одной функции.
- **Ссылка outer фиксируется раньше вызова — при создании функции.** Функция запоминает окружение, где её написали (внутреннее поле `[[Environment]]`), и новый контекст при вызове берёт outer оттуда. Поэтому scope лексический.
- **Блок `{ }` с `let`/`const` контекст не создаёт**, только новое Lexical Environment внутри текущего контекста.

## Call stack — это стек контекстов
В спецификации он так и называется: **execution context stack**. Элемент стека — контекст. «Вызов функции» — это момент, когда наверх кладут новый контекст; отдельной записи «вызов» нет. Строка в панели Call Stack в DevTools — один контекст.

```js
function f(n) {
  if (n === 0) return;
  f(n - 1);
}
f(2);
```

```
f(n=0)   ← вершина: выполняется сейчас
f(n=1)
f(n=2)
global   ← положен при старте скрипта, в DevTools это (anonymous)
```

1. Вызов: новый контекст кладут наверх, проходит фаза создания (параметры, hoisting, `this`).
2. Выполняется тело.
3. `return`: контекст снимают, выполнение продолжается в контексте под ним.

**Глобальный контекст тоже снимается.** Когда скрипт выполнился до конца, стек пустеет. Колбэки (`setTimeout`, события, промисы) event loop запускает уже на пустом стеке, поэтому в их стектрейсе нет строк исходного скрипта.

**Контекст и окружение живут по-разному.**
- Контекст — запись «что выполняется сейчас». Живёт, пока идёт выполнение.
- Окружение (Lexical Environment) — переменные. Живёт, пока на него кто-то ссылается.

Поэтому глобальные переменные переживают снятие глобального контекста, а локальные переменные `outer()` — её `return`, если на них ссылается замыкание.

**Генераторы и `async`-функции** уходят со стека и возвращаются. На `yield` или `await` контекст снимают, но не уничтожают, а приостанавливают. На `next()` или при разрешении промиса **тот же** контекст кладут обратно, с теми же локальными переменными. Контекст обычной функции после `return` не возвращается никогда.

```js
function* gen() {
  const x = 1;
  yield x;      // контекст снят со стека, но сохранён
  yield x + 1;  // на next() тот же контекст вернулся, x всё ещё 1
}
```

**Это модель спецификации, а не устройство движка.** V8 хранит машинные фреймы, а маленькую функцию может встроить в вызывающую (inlining), и тогда своего фрейма у неё нет. Стектрейсы движок восстанавливает, так что для понимания модель «стек контекстов» верна.

## Две фазы
1. **Создание** — регистрация объявлений (hoisting):
   - function declaration — поднимается **целиком**, её можно вызвать до объявления;
   - `var` — поднимается со значением `undefined`;
   - `let` / `const` / `class` — регистрируются, но до строки объявления находятся в **TDZ** (обращение → `ReferenceError`).
2. **Выполнение** — код выполняется построчно.

## Виды функций
| | свой `this` | `arguments` | `new` | hoisting |
|---|---|---|---|---|
| declaration | да | да | да | целиком |
| expression | да | да | да | как переменная |
| arrow | нет (лексический) | нет | нет | как переменная |
| method (`{ m() {} }`) | да | да | нет | — |

Также есть `async` (возвращает промис, `await` отдаёт управление) и генераторы (контекст можно приостановить и возобновить).

Функции — **first-class**: значения, которые можно передавать, возвращать и хранить.

## Частые ошибки понимания
- Hoisting «переносит код наверх». Нет: объявления регистрируются в фазе создания.
- `let` / `const` не поднимаются. Поднимаются, но в TDZ.
- Scope зависит от того, где функцию вызвали. Нет: он лексический. От места вызова зависит только `this`.
- Контекст функции создаётся один раз при объявлении. Нет: при объявлении фиксируется только outer, а контекст создаётся заново на каждый вызов.
- В стек кладут «вызов», а контекст — что-то отдельное. Нет: call stack и есть стек контекстов.
- Глобальный контекст лежит на стеке всё время. Нет: после выполнения скрипта стек пустеет, колбэки стартуют на пустом стеке.
- Снят контекст — пропали переменные. Нет: окружение живёт, пока на него ссылаются (замыкания, глобальные переменные).
- Каждый блок `{ }` создаёт контекст. Нет: только новое Lexical Environment.
