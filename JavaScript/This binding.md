# This binding

**Определение.** `this` — не переменная из области видимости, а **привязка, которая определяется в момент вызова** функции (call site). Исключение — стрелочные функции.

## Правила (по приоритету)
1. **`new`** — `new Foo()`: `this` — новый объект.
2. **Явная привязка** — `fn.call(obj)`, `fn.apply(obj)`, `fn.bind(obj)`. `bind` возвращает жёстко привязанную функцию, и повторный `bind` её не изменит.
3. **Неявная** — `obj.method()`: `this === obj` (объект слева от точки в момент вызова).
4. **По умолчанию** — просто `fn()`: `undefined` в strict mode (модули и классы всегда strict), `globalThis` в sloppy.

**Стрелочные функции** не имеют своего `this`. Они берут его из окружающей лексической области, и `call` / `bind` на них не действуют.

## Где это важно
- Методы классов, переданные как колбэк (`onClick={this.handle}`, `arr.map(obj.method)`), **теряют** `this`. Решения: `bind` в конструкторе, поле-стрелка (`handle = () => {}`), обёртка `() => obj.method()`.
- Обработчики DOM-событий через `addEventListener` с обычной функцией: `this` — элемент.
- Стрелки как методы объекта: `this` будет внешний, а не объект.

## Частые ошибки понимания
- `this` указывает на саму функцию или на её область видимости — нет.
- `this` определяется там, где функция объявлена, — это верно только для стрелок.
- Думать, что `const f = obj.method; f()` сохранит `obj`: неявная привязка теряется.
