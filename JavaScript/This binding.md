# This binding

**Определение.** `this` — не переменная из области видимости, а **привязка, которая определяется в момент вызова** функции (call site). Исключение — стрелочные функции.

## Правила (по приоритету)
1. **`new`** — `new Foo()`: `this` — новый объект.
2. **Явная привязка** — `fn.call(obj)`, `fn.apply(obj)`, `fn.bind(obj)`.
3. **Неявная** — `obj.method()`: `this === obj` (объект слева от точки в момент вызова).
4. **По умолчанию** — просто `fn()`: `undefined` в strict mode (модули и классы всегда strict), `globalThis` в sloppy.

У обычной функции `this` **никогда не наследуется** из внешнего кода, его задаёт только способ вызова.

**Strict mode** включается автоматически в ES-модулях и в теле `class`. Поэтому `const f = obj.method; f()` получает `this === undefined` и падает с `TypeError: Cannot read properties of undefined`, если метод читает свойство `this`. В обычном скрипте без strict `this` будет `globalThis`: ошибки нет, но и данных объекта тоже.

## `bind`, `call`, `apply`
- `call` и `apply` вызывают функцию сразу с заданным `this` (аргументы списком или массивом).
- `bind` возвращает **новую** функцию с зашитым `this`. `call`, `apply` и повторный `bind` на ней `this` не меняют. Перебить привязку может только `new`.
- Исходная функция при этом не меняется: `f.call(x)` на ней работает как обычно.

```js
function who() { return this.name; }
const bound = who.bind({ name: 'A' });
bound.call({ name: 'B' });      // 'A' — привязку не перебить
who.call({ name: 'B' });        // 'B' — исходная функция свободна
```

## Что делает `new`
1. Создаёт пустой объект с прототипом `F.prototype`.
2. Вызывает `F` с `this` = этот объект.
3. Возвращает `this`, если конструктор не вернул другой **объект**. Возвращённый примитив игнорируется.

Что такое `F.prototype` и цепочка прототипов — в [[Прототипы]].

## Стрелочные функции
- Своего `this` нет: он ищется в окружении, как обычная переменная, то есть определяется местом написания.
- Нет `arguments` и `prototype`, нельзя вызвать через `new`. `call`, `apply` и `bind` их `this` не меняют.
- **Объектный литерал не создаёт область видимости.** `{ name: 'x', get: () => this.name }` берёт `this` снаружи объекта, а не сам объект.

```js
const obj = {
  name: 'obj',
  regular() {
    function inner() { return this; }      // свой this: вызов без точки → undefined
    const arrow = () => this;              // this метода → obj
    return [inner(), arrow()];
  },
};
obj.regular(); // [undefined, obj]
```

## `this` верхнего уровня файла
Задаёт среда, а не язык:

| Где | `this` | Совпадает с `globalThis`? |
|---|---|---|
| ES-модуль | `undefined` | Нет |
| `<script>` в браузере | `window` | Да |
| Node, CommonJS | `module.exports` (`{}`) | Нет |

Модулем файл становится так: в браузере `<script type="module">`, в Node — `"type": "module"` в `package.json` или расширение `.mjs`. Расширение `.cjs` всегда означает CommonJS.

## Где это важно
- Методы классов, переданные как колбэк (`onClick={this.handle}`, `arr.map(obj.method)`), **теряют** `this`. Решения: `bind` в конструкторе, поле-стрелка (`handle = () => {}`), обёртка `() => obj.method()`.
- React, классовый компонент: `onClick={function () { this.handle() }}` проблему не решает, у обычной функции свой `this`. Работают `onClick={() => this.handle()}` и поле-стрелка. Стрелка прямо в JSX создаёт новую функцию на каждый рендер; это важно, только если ребёнок мемоизирован.
- Внутренняя `function` внутри метода получает свой `this` (её вызывают без точки), а не `this` метода. Лечится стрелкой.
- Обработчики DOM-событий через `addEventListener` с обычной функцией: `this` — элемент.
- Стрелки как методы объекта: `this` будет внешний, а не объект.

## Частые ошибки понимания
- `this` указывает на саму функцию или на её область видимости — нет.
- `this` определяется там, где функция объявлена, — это верно только для стрелок.
- Думать, что `const f = obj.method; f()` сохранит `obj`: неявная привязка теряется.
- «`call` перебьёт `bind`». Нет, перебить `bind` может только `new`.
- «`this` верхнего уровня — это всегда `globalThis`». Только в обычном `<script>` браузера.
- «Стрелка в объектном литерале видит объект». Литерал не создаёт область видимости.

## Связи
- [[Функции и execution context]] — `this` — часть execution context, он задаётся при создании контекста вызова.
- [[Closures]] — стрелочные функции «замыкают» `this` так же, как переменные.
- [[Прототипы]] — `new` ставит `[[Prototype]]` экземпляра в `F.prototype`. Методы класса лежат на прототипе, поэтому теряют `this` в колбэке.
