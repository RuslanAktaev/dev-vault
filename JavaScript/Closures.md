# Closures

**Определение.** Замыкание — функция вместе со **ссылкой** на лексическое окружение, в котором она была создана. Это не копия значений и не контекст вызова. Функция «помнит» переменные внешней области видимости даже после того, как внешняя функция завершилась.

```js
function counter() {
  let n = 0;
  return () => ++n;   // замыкает n
}
const next = counter();
next(); next(); // 2
```

## Ключевая идея
- Захватывается **переменная (binding), а не её значение**. Если переменная изменится, замыкание увидит новое значение.
- Замыкание создаётся **при каждом вызове** внешней функции. Каждый вызов даёт новое окружение, поэтому два счётчика из двух вызовов `counter()` независимы.
- Окружение живёт, пока на него есть ссылка, даже после того как внешняя функция завершилась и её контекст снят со стека.
- Область видимости **лексическая**: определяется тем, где функция написана, а не тем, где вызвана.

## Где применяется
Приватное состояние и модули, фабрики функций, частичное применение и каррирование, memoize, обработчики событий и колбэки, хуки React (каждый рендер — новое замыкание над props и state).

## Частые ошибки понимания
- **`var` в цикле.** `var` — одна переменная на всю функцию, и все колбэки замыкают её. Вызываются они после цикла, когда `i` уже 3. `let` создаёт новое окружение на каждую итерацию. Причина не в `setTimeout`, а в общей переменной и вызове после её изменения.

```js
for (var i = 0; i < 3; i++) setTimeout(() => console.log(i)); // 3 3 3
for (let j = 0; j < 3; j++) setTimeout(() => console.log(j)); // 0 1 2
```
- **Stale closure в React**: `useEffect` / `setInterval` / `useCallback` с неполными зависимостями видят значения из старого рендера. Лечится правильными deps, функциональным `setState(prev => …)` или `useRef`.
- **Утечки памяти**: замыкание удерживает всё окружение. Долгоживущий обработчик держит большие объекты.
- «Замыкание копирует значения» — нет, см. выше.
