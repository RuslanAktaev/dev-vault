# Declarations

**Определение.** Объявления в TS создают сущности в одном или нескольких **пространствах имён**: *значений* (value), *типов* (type) и *namespace*. Отдельный вид — **ambient-объявления** (`declare`, `.d.ts`), которые описывают то, что существует в рантайме, но не генерируют JS.

## Пространства объявлений
| Объявление | value | type |
|---|---|---|
| `interface`, `type` | — | ✔ |
| `const` / `let` / `function` | ✔ | — |
| `class`, `enum` | ✔ | ✔ |
| `namespace` | ✔ (если есть значения) | ✔ |

Поэтому `class Foo` можно использовать и как значение, и как тип, а `interface` — только как тип.

## Declaration merging
- Одноимённые **interface** сливаются в один. `type` так не умеет, будет ошибка дубликата.
- `namespace` сливается с `function`, `class`, `enum`: так к функции добавляют статические свойства.
- **Module augmentation**: `declare module 'lib' { interface X { extra: string } }` расширяет типы чужой библиотеки.
- **Global augmentation**: `declare global { interface Window { … } }`. Работает только в файле-модуле (нужен хотя бы `export {}`).

## Ambient и `.d.ts`
- `declare const __DEV__: boolean;` — сообщить компилятору о глобальной переменной.
- `declare module '*.svg'` — типы для импортов не-TS файлов.
- `.d.ts` без top-level `import` / `export` — **глобальный скрипт**, его объявления видны везде. С `import` он становится модулем.
- Типы библиотек: встроенные (`types` в `package.json`) или `@types/*`. `lib.d.ts` задаётся опцией `lib`.
- `declaration: true` — компилятор генерирует `.d.ts` для твоего кода (библиотеки, Nx-пакеты).

## Частые ошибки понимания
- `declare` что-то создаёт. Нет: это обещание компилятору. Если в рантайме этого нет, будет ошибка.
- `type` и `interface` взаимозаменяемы. Почти, но слияние и augmentation возможны только у `interface`.
- Добавить `import` в `global.d.ts` и удивиться, что глобальные типы пропали: файл стал модулем.
