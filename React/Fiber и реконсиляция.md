# Fiber и реконсиляция

**Определение.** Fiber — долгоживущий JS-объект, узел внутреннего дерева React. Реконсилер — алгоритм, который сравнивает новые React-элементы с этим деревом и решает, что изменить. Рендерер применяет изменения к платформе. Fiber — это структура данных и архитектура, на которой работает реконсилер, а не имя реконсилера.

## Термины

| Термин | Что это |
|---|---|
| React-элемент | Лёгкий объект `{ type, props, key }`, который возвращает JSX. Создаётся заново при каждом рендере |
| Fiber | Узел внутреннего дерева. Один файбер на **узел дерева**, не обязательно компонент: экземпляр компонента, хост-элемент (`div`, `View`), текст, служебные узлы (Fragment, Suspense, Provider, memo). Отрисовал `<Button />` 10 раз — 10 файберов |
| Реконсилер | Алгоритм сравнения. Сам DOM и нативные view не трогает |
| Рендерер | Применяет изменения к платформе: `react-dom` (DOM), Fabric (React Native) |
| Виртуальный DOM | Общее название идеи, подробнее в [[Virtual DOM]] |

## Что хранит файбер (упрощённо)
- `type`, `key`, `tag` (вид узла).
- `pendingProps` / `memoizedProps` — новые и применённые props.
- `memoizedState` — у функционального компонента **связный список хуков**.
- `stateNode` — реальный DOM-узел, нативный view или экземпляр класса. У функциональных компонентов пусто.
- `return` (родитель), `child`, `sibling` — дерево хранится связным списком, а не рекурсией. Обход идёт циклом, и его можно **прервать и продолжить**. Ради этого Fiber и придумали.
- `flags` — что сделать в commit: вставка, обновление, удаление, эффекты.
- `lanes` — приоритет работы; `childLanes` — «в поддереве есть работа».
- `alternate` — парный файбер из другого дерева.

Названия полей меняются между версиями (`effectTag` стал `flags`), важна идея.

## Два дерева
- **current** — то, что сейчас на экране.
- **work-in-progress** — строится при новом рендере.
- После commit они меняются местами сменой указателя. Файберы связаны через `alternate`, поэтому память переиспользуется.

## Как проходит ререндер
1. Компоненты вызываются и возвращают **новые элементы**. Дерево элементов перестраивается, кроме пропущенных поддеревьев.
2. Реконсилер сравнивает новые элементы с **текущими файберами** по `type` и `key`. Старые элементы React не хранит, сравнивать не с чем.
   - Тот же `type` и `key` — файбер переиспользуется через `alternate`, получает новые `pendingProps`.
   - Другой `type` или такого `key` нет — старый файбер помечается на удаление, создаётся новый, state теряется.
3. Расставляются `flags`.
4. Commit: рендерер применяет флаги к реальному UI.

Дерево файберов **не создаётся с нуля**, а обновляется.

**Bailout.** Если props, state и контекст не менялись, поддерево пропускается. На этом работает `React.memo`. Без memo ререндер родителя тянет за собой детей: элементы созданы заново, и props считаются новыми, даже если значения те же.

**Эвристики для O(n).** Разные типы — пересоздать поддерево. Списки сопоставляются по `key`. Индекс как `key` ломает состояние в изменяемых списках.

## Две фазы
- **Render (reconciliation)** — чистая, без побочных эффектов. В concurrent-режиме **прерываемая**: React может отложить её ради более срочной работы или выполнить повторно.
- **Commit** — синхронная, без прерываний. Применяются изменения, затем `useLayoutEffect`, затем `useEffect`.

## Коротко для собеседования
- **Fiber**: внутреннее дерево React, узел на каждый компонент, DOM-элемент и текст. Хранит тип, props, state (хуки), ссылку на DOM, связи `child`/`sibling`/`return`. Благодаря связному списку render прерываем. Два дерева: current и work-in-progress.
- **Fiber против Fabric**: Fiber — реконсилер React (JS), Fabric — рендерер React Native (C++). Fiber решает, что изменилось, Fabric доставляет это в нативный UI.

## Частые ошибки понимания
- **«Реконсилер называется Fiber».** Fiber — структура данных и архитектура, реконсилер — алгоритм поверх неё.
- **«Один файбер на компонент».** На каждый узел дерева, включая `div`, текст и служебные узлы. И на каждый экземпляр, а не на определение компонента.
- **«React сравнивает новое дерево элементов со старым».** Со старыми файберами: старые элементы не хранятся.
- **«Ререндер строит дерево файберов заново».** Файберы переиспользуются через `alternate`.
- **«Реконсилер меняет DOM».** Это делает рендерер в commit.
