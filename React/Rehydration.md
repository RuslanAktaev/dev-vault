# Rehydration

Термин используется в двух смыслах, их полезно различать.

## 1. Гидрация разметки (SSR → клиент)
Сервер отдаёт готовый HTML. Клиентский React **не создаёт DOM заново**, а проходит по существующему, строит своё дерево, навешивает обработчики событий и делает страницу интерактивной (`hydrateRoot`).
- **Hydration mismatch.** Клиентский рендер должен совпасть с серверным. Типичные причины расхождения: `Date.now()`, `Math.random()`, `typeof window` в рендере, локаль и таймзона, расширения браузера, невалидная вложенность HTML.
- Правильно: всё, что зависит от клиента, делать в `useEffect`, после гидрации.
- **Selective hydration** (React 18): части под Suspense гидрируются независимо, в приоритете та часть, с которой пользователь взаимодействует.
- До окончания гидрации страница видна, но не интерактивна. Метрики: TTI / INP.

## 2. Регидрация состояния
Восстановление состояния стора из внешнего источника:
- **Persist** (`redux-persist`): состояние загружается из `localStorage` / `AsyncStorage` **асинхронно**. Первый рендер происходит с начальным состоянием, поэтому нужен `PersistGate` или флаг `_persist.rehydrated`.
- **SSR state transfer**: стор заполняется на сервере, сериализуется в HTML (`window.__PRELOADED_STATE__`) и используется как начальное состояние на клиенте. В RTK Query для этого есть `extractRehydrationInfo`.

## Частые ошибки понимания
- Гидрация = повторный рендер с нуля. Нет: DOM переиспользуется. При mismatch React может перерендерить поддерево на клиенте, и это дорого.
- Прятать mismatch через `suppressHydrationWarning` вместо того, чтобы устранить причину.
- Считать, что после `store` сразу всё готово. При persist данные появятся позже.
- Персистить кэш RTK Query вместе со всем стором и получать устаревшие данные.

## Связи
- [[Virtual DOM]] — гидрация — это reconciliation поверх уже существующего DOM.
- [[Event Loop]] — регидрация стора асинхронна: восстановление приходит после первого рендера.
- [[RTK Query]] — передача кэша с сервера на клиент и конфликты с persist.
- [[SSR-SSG-ISR]] — любой HTML с сервера (SSR, SSG, ISR) затем гидрируется.
- [[App Router и Server Components]] — гидрируются только client components, серверные компоненты в клиентский JS не попадают.
