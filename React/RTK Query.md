# RTK Query

**Определение.** Слой загрузки и кэширования серверных данных поверх Redux Toolkit. Описываешь эндпоинты, а RTK Query сам генерирует хуки, редьюсер и middleware с кэшем.

## Ключевые понятия
- `createApi({ baseQuery, endpoints })` — одно API на один бэкенд. `query` — чтение, `mutation` — изменение.
- **Кэш-ключ = эндпоинт + сериализованные аргументы.** `getUser(1)` и `getUser(2)` — разные записи.
- **Подписки.** Каждый компонент, который вызвал хук, — подписчик. Когда подписчиков нет, запись удаляется через `keepUnusedDataFor` (по умолчанию 60 с).
- **Дедупликация.** Десять компонентов с одним запросом → один сетевой запрос.
- **Теги.** `providesTags` на query, `invalidatesTags` на mutation. После мутации активные запросы с этими тегами перезапрашиваются автоматически.
- `isLoading` — первая загрузка без данных. `isFetching` — любой запрос, включая рефетч при уже показанных данных.
- **Optimistic update**: `onQueryStarted` + `api.util.updateQueryData`, при ошибке `patch.undo()`.
- Полезное: `skip` / `skipToken`, `pollingInterval`, `refetchOnFocus` / `refetchOnReconnect` (нужен `setupListeners`), `selectFromResult` для точечных ререндеров.

## Где применяется
Серверное состояние: списки, детали, CRUD. В Nx лежит в `data-access`-библиотеке, фичи используют хуки.

## Частые ошибки понимания
- Использовать его для клиентского состояния (открыта ли модалка, форма). Для этого есть slice или локальный state.
- Ждать, что мутация сама обновит список. Без тегов или ручного `updateQueryData` ничего не произойдёт.
- Путать `isLoading` и `isFetching` → при рефетче мигает скелетон.
- Передавать в хук новый объект аргументов на каждом рендере. Сериализация стабильна, но лишние вычисления и вопросы к `skip` всё равно остаются.
- `unwrap()` у мутации: без него ошибка не бросается, а приходит в результате.

## Связи
- [[Event Loop]] — запросы — промисы, обновления стора приходят в микротасках и тасках. Отсюда состояния `pending` / `fulfilled` и гонки.
- [[Rehydration]] — при SSR кэш RTK Query заполняется на сервере и восстанавливается на клиенте (`extractRehydrationInfo`). Также он может конфликтовать с redux-persist.
- [[Nx монорепа]] — API-слайсы живут в `data-access`, отделённые от UI.
- [[Идемпотентность и чистые функции]] — query соответствует safe и cacheable чтению, mutation не safe и требует инвалидации кеша; повторять мутацию безопасно только если она идемпотентна.
