# setState и хуки

**Определение.** `setState` не рендерит и не вызывает компонент. Он кладёт обновление в очередь хука, помечает файбер и планирует render. Сам хук — объект в связном списке файбера, а вызов `useState()` в компоненте — запрос «дай хук номер N моего файбера».

## Что происходит при вызове `setState`
1. Объект-обновление кладётся в `queue` **хука**: объекта в списке `fiber.memoizedState`.
2. Файбер получает lane (приоритет), у предков до корня ставится `childLanes` — «в поддереве есть работа». Метки нужны, чтобы render дошёл сверху вниз до нужного файбера и пропустил ветки без работы, а не чтобы перерисовать родителей.
3. Планируется render с учётом приоритетов и батчинга.

**Eager bailout.** Если других ожидающих обновлений нет, React может сразу сравнить новое значение со старым через `Object.is` и не планировать render вообще. Срабатывает не всегда, полагаться на это нельзя.

## Когда выполнится render

| Откуда обновление | Когда render |
|---|---|
| Дискретное событие: клик, ввод | В конце обработчика, микрозадачей |
| Таймеры, сеть, прочее | Отдельной макрозадачей через Scheduler React |
| `startTransition`, `useDeferredValue` | С низким приоритетом, render прерываемый |

**Батчинг** с React 18 автоматический везде, включая `setTimeout`, промисы и нативные обработчики: несколько `setState` подряд дают один render.

## `count` — константа рендера
Каждый рендер — отдельный вызов функции компонента, и `count` в нём — значение из этого рендера, захваченное замыканием.

```js
setCount(count + 1);
setCount(count + 1);  // итог +1, а не +2: оба раза count одинаковый
setCount(c => c + 1); // апдейтер получает актуальное значение из очереди
```

## Хуки живут в файбере
- Вызов `useState()` ничего не хранит, он читает хук по порядковому номеру из файбера.
- Реальное хранилище — объект хука в связном списке `fiber.memoizedState`: `memoizedState` (значение), `queue` (обновления), `next` (следующий хук).
- `setState` — диспетчер, привязанный замыканием к конкретному файберу и его очереди. Поэтому его можно передавать куда угодно, и он стабилен между рендерами.
- Хуки сопоставляются **по позиции** в списке. Вызов в `if` или цикле сдвигает порядок, и состояния перепутаются. Отсюда правила хуков.
- Состояние переживает ререндеры, потому что лежит в файбере, а не в функции компонента.

## Частые ошибки понимания
- **«`setState` сразу перерисовывает».** Он только ставит обновление в очередь и планирует render.
- **«После `setState` переменная обновится».** В текущем рендере `count` — константа. Новое значение будет в следующем вызове компонента.
- **«`childLanes` перерисовывает родителей».** Это навигация для render, родители без своих обновлений делают bailout.
- **«Состояние хранится в функции компонента».** В файбере. Функция вызывается заново каждый рендер.
- **«Хук можно вызвать в условии, если условие стабильно».** Правило о порядке вызовов; линтер требует безусловных вызовов.
