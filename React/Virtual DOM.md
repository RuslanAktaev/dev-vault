# Virtual DOM

**Определение.** Virtual DOM — дерево обычных JS-объектов (React elements), которое описывает, как должен выглядеть UI. React сравнивает новое дерево с предыдущим и вносит в настоящий DOM минимальные изменения.

## Как работает
1. **Render phase** — вызываются компоненты, получается новое дерево элементов. Фаза должна быть **чистой**: без побочных эффектов. Её можно прервать, отложить или выполнить повторно.
2. **Reconciliation** — сравнение (diffing) со старым деревом за O(n) по эвристикам:
   - другой тип элемента → поддерево размонтируется и монтируется заново (state теряется);
   - тот же тип → обновляются props, рекурсия по детям;
   - в списках идентичность элементов определяется по `key`.
3. **Commit phase** — изменения применяются к хосту (DOM), затем запускаются эффекты (`useLayoutEffect` синхронно, `useEffect` после отрисовки).

**Fiber** — внутренняя реализация reconciler: работа разбита на единицы, у обновлений есть приоритеты. На этом построены concurrent-фичи (`startTransition`, Suspense).

## Ключевая идея
Главное в VDOM — не скорость, а **декларативная модель**: описываешь состояние UI, а не шаги по его изменению. Reconciler отделён от хоста: один и тот же React рисует в DOM (react-dom), в нативные view (React Native) или куда угодно ещё.

## Частые ошибки понимания
- «VDOM быстрее DOM». Нет: это накладные расходы поверх DOM. Выигрыш — в батчинге и минимальных мутациях по сравнению с наивным «перерисовать всё».
- **Re-render ≠ обновление DOM.** Компонент может перерендериться, а DOM не изменится.
- `key={index}` в изменяемых списках: при вставке или удалении state и DOM «переезжают» к чужим элементам.
- Смена типа компонента-обёртки (например, компонент, объявленный внутри другого компонента) на каждом рендере → полный remount.

## Связи
- [[New Architecture]] — тот же reconciler, но хост другой: Fabric коммитит в нативный shadow tree, а не в DOM. Две модели рендеринга поверх одной идеи.
- [[Rehydration]] — при гидрации React строит дерево и «прикрепляет» его к уже готовому HTML вместо создания DOM.
- [[App Router и Server Components]] — RSC payload — сериализованное дерево элементов, которое клиент reconcile-ит так же.
